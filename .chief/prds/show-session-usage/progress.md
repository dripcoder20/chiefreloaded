# Progress: Show Session Usage

## Codebase Patterns
- **`loopctl` is the headless test seam (US-009)**: any read model that needs e2e coverage gets a `loopctl` subcommand emitting it as JSON (`loopctl usage -json` → the full `session.UsageReport`). E2e tests then assert real parse→attribute→aggregate→persist without a window. The "status bar" totals are just `usage.runs[runId]` / `usage.stories[runId/storyId]` slices of that report, so one JSON assertion covers them. Per-attempt scope keys use the **global** run attempt counter (`run.attempt`), so a retried story shows non-consecutive `#n` (US-002 → `#2`/`#3`); assert by counting keys with the story prefix, not exact numbers. A model-only Claude assistant line (no `usage`) still yields a zero-token record — put the model on the `result` line in scripted agents.
- **Binding-free frontend module for Vitest (US-009)**: the Wails bindings (`frontend/bindings/`) and `frontend/dist` are generated at build time and absent in a fresh worktree, so anything importing `../platform` can't be svelte-checked or unit-tested here. Keep pure logic in a module that imports nothing from `../platform` — `frontend/src/stores/usage.ts` holds the usage types + presentation helpers; `app.svelte.ts` re-exports it so components are unchanged. Vitest runs it via a standalone `frontend/vitest.config.ts` (NOT `vite.config.ts`, which loads the Wails plugin). `npm test` / `task test:frontend`.
- **Grouped usage read model (US-006)**: `session.UsageTotals` now carries `Groups []UsageGroup` — a per-(provider, model, currency) subtotal built in `UsageTotals.foldGroup`/`UsageGroup.addRecord`. Flat fields stay the grand sum; groups keep mixed usage separate. Because `UsageTotals` now contains a slice it is **no longer comparable** — replace any `totals == other`/`!=` in tests with `reflect.DeepEqual`. `UsageRecord` gained `ContextWindow *int64` and `Estimated bool` (cost kind); `resolveCost` returns `(*float64, estimated bool)`. Cost kind on a group is `reported`/`estimated`/`mixed` via `noteCostKind`.
- **Loop config: Normalise fills, Validate rejects (US-007)**: `.chief/config.yaml` settings live in `internal/chief/config/config_ext.go` (`LoopConfig`). A new block is: a struct with `yaml:` tags, a field on `LoopConfig`, defaults in `DefaultLoop()`, a `*T` pointer in `rawConfig` (`rawio_ext.go`) copied in `LoadLoop`/`saveRaw`, plus the UI bridge in `internal/session/settings.go` (`settingsFrom`/`toConfig`, with json-tagged mirror types) and mock `getConfig`. **Split normalisation from validation**: `Normalise()` fills *unset* (zero) fields from defaults (a zero is "unset", not a deliberate 0); `LoopConfig.Validate()` rejects values the user actually chose (out-of-range, cross-field like "critical > warning"). `Session.SaveLoopConfig` calls `Normalise()` then `Validate()` then save — a rejected value returns an error, and `Settings.svelte`'s `update()` shows it via `app.error` and does not adopt the config, so nothing invalid reaches disk.
- **Frontend usage panel (US-006)**: `frontend/src/views/UsagePanel.svelte` is a modal dialog opened from `UsageBar`'s trigger button. It reads `app` directly (like Inspector/StoryList), not props. Scopes: Story = `usage.stories[run.id/storyId]`, Session = `usage.runs[run.id]`, General = `usage.project` (`app.generalUsage`). Keyboard: tablist arrow-nav (roving `tabindex`), `Tab` trapped inside the dialog, `Escape` closes; the trigger (`bind:this`) is refocused on close. `{@const}` must be a direct child of a block (`{#each}`/`{#if}`), NOT of a plain `<div>` — build a single rows array in the script and iterate once instead of sprinkling `{@const}` between elements.

- **Two checkouts, ALWAYS edit the worktree**: the recurring gotcha bit again. `/Users/kristher/Code/DripCoder/loop/frontend/...` is the MAIN repo; the story worktree is `/Users/kristher/Code/DripCoder/loop/.chief/worktrees/show-session-usage/frontend/...`. They can be byte-identical (`diff` to confirm) but the Read/Edit tools track state per absolute path, so editing the main path leaves the worktree untouched and vice-versa. Read + edit + commit exclusively under the worktree path.
- **Frontend tooling is absent in a fresh worktree**: `frontend/node_modules/` AND `frontend/bindings/` are both gitignored/Wails-generated, so `npm run check` / `svelte-check` / `vite build` cannot run here. TS diagnostics for `$state`/`$props` runes and "implicit any" on `.find((r) => ...)` are environmental (no svelte-check config, no generated types) and pre-exist across every `.svelte`/`app.svelte.ts` file — they are NOT introduced by an edit. Validate frontend logic by structural review; only the Go side (`go build ./internal/...`) actually compiles here.
- **Frontend↔Go type contract without bindings**: mirror Go json tags as plain local TS types and cast at the boundary (`(snap as { usage?: UsageReport }).usage`). This is the same trick `mock.ts` uses. Keep field names camelCase to match the Go `json:"..."` tags (`runId`, `storyId`, `totalTokens`, `cacheReadTokens`, etc.). Report keys: `runs[runId]`, `stories[runId/storyId]`, `attempts[runId/storyId#n]`.
- **Live state flows two ways**: adopt `Snapshot.usage` wholesale in `refresh()`, then replace `app.usage` on every `EvUsage` event (its `usageReport` is an ABSOLUTE roll-up, never a delta — assign, don't add). `EvUsage` is deliberately NOT in `LOG_KINDS`, so it reaches `apply()` and drives state instead of the log ring buffer.
- **Parsers live in `internal/chief/loop/`**: `parser.go` (Claude), `codex_parser.go`, `cursor_parser.go`, `opencode_parser.go`. Each exposes `ParseLine*(line string) *Event` and returns `nil` for irrelevant lines. The active `Loop.processOutput` calls `provider.ParseLine`; events flow through a channel and only `EventStoryDone`/`EventComplete` get special handling, so new event types pass through harmlessly.
- **`third_party/chief/` is a SEPARATE Go module** (`third_party/chief/go.mod`) — it is NOT part of `github.com/dripcoder/loop` and does not need to be edited or kept in sync.
- **Optional vs zero**: use pointer fields (`*int64`, `*float64`) with `json.RawMessage` for sub-objects so a missing JSON key stays `nil` and a reported `0` is preserved. Plain `int`/`float64` cannot distinguish the two.
- **Malformed-payload handling**: parse the sub-object as `json.RawMessage` first, then `json.Unmarshal` into the typed struct; on error emit `warningEvent(provider, err)` (an `EventWarning`) so the run continues instead of crashing.
- **Tests**: standard Go table/case tests co-located as `*_test.go`; JSON fixtures are inline string literals. Shared assert helpers (`assertInt64Ptr`, `assertFloatPtr`, `usageEvent`) live in `usage_test.go`.
- **Quality checks**: `go build ./...`, `go vet ./...`, `go test ./...`, `gofmt -l`. No Makefile, no golangci-lint. (Linker prints harmless `ld: warning ... newer macOS` lines — ignore them.)
- **Provider usage field names**:
  - Claude assistant `message.usage`: `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`; model at `message.model`. Result line: top-level `total_cost_usd` + `usage`.
  - Codex `turn.completed.usage`: `input_tokens`, `cached_input_tokens` (→ cache read), `output_tokens`.
  - OpenCode `step_finish.part`: `tokens.{input,output,reasoning,cache.{read,write}}` + `cost`.
  - Cursor `result` line mirrors Claude's usage shape (`usage.{input_tokens,output_tokens,cache_read_input_tokens,cache_creation_input_tokens}` + `total_cost_usd`).
- **Two layers, two Usage models**: the vendored `internal/chief/loop` package normalizes per-payload usage (`loop.Usage`, US-001). The `internal/session` package attributes and aggregates it (`session.UsageRecord` / `UsageTotals` / `UsageReport`, US-002). The bridge is `run.forwardAgentEvents`, which turns `loop.Event.Usage` into an attributed `session.UsageRecord`. Keep provider-shape parsing in the loop package and attribution/aggregation in the session package.
- **Attribution flows through `run.forwardAgentEvents`** (`internal/session/run.go`): every `loop.Event` with a non-nil `Usage` (whether a usage-only event or usage riding on assistant text) is fed to `run.recordUsage(storyID, attempt, usage)`. That is the single place run/story/attempt/provider context is stamped onto a usage payload.
- **The `session.Session` owns a `*usageLedger`** (`internal/session/usage.go`): dedups by stable `Key`, keeps records, and rebuilds `UsageReport` on demand. Reset in place (`ledger.reset()`) on `OpenProject`, never reassigned, so live run goroutines holding `r.sess.usage` don't race the pointer.
- **`fakeagent.Behaviour.Usage`** (`*fakeagent.Usage`) emits a Claude-style `result` line, so run-engine tests exercise the real parse→forward→attribute→aggregate path. It is emitted before any `ExitCode` exit, so a crashing attempt still reports usage (needed to test retry/failure attribution).
- **Usage persistence lives in `internal/session/usage_store.go`** (`.chief/usage.json`, versioned envelope `{version, records}`). Writes are atomic (temp file in the same dir + `os.Rename`). The `usageLedger` owns an optional `*usageStore`; `add` persists inside the same lock that appends, so concurrent updates can never clobber the file with a stale subset. `OpenProject` calls `ledger.open(store, records, log)` (replaces the old `reset()`), loading persisted history and restoring per-scope key counters. A load error is surfaced as an `EvUsageError` event and treated as empty history — it never fails `OpenProject`. `OpenProject` also bumps `runSeq` past the highest persisted `run_<n>` so a new run cannot merge into a historical run's totals.

## 2026-08-02 - US-003 Persist project usage history
- Added `internal/session/usage_store.go`: a versioned, atomically-written `.chief/usage.json` store (`load`/`save`). Missing/empty file → empty history (no error); malformed JSON or unsupported version → error. `save` MkdirAll's `.chief/` and writes via temp-file + rename so an interrupted write can't leave a partial file.
- Made `usageLedger` persist: it now holds an optional `*usageStore` + `*slog.Logger`. `add` persists inside the append lock (last serialized write is always the most complete — no stale clobber under concurrency). Replaced `reset()` with `open(store, records, log)`, which loads persisted records in place and restores per-attempt key counters (`restoreCounterLocked`) so freshly assigned keys don't collide with loaded ones.
- Wired into `Session.OpenProject`: loads the store before taking the lock, calls `ledger.open`, bumps `runSeq` past any persisted `run_<n>`, and on load error publishes a new `EvUsageError` event (actionable hint) without failing the open — PRD list and run controls stay usable.
- Files changed:
  - `internal/session/usage_store.go` (new — store + atomic write)
  - `internal/session/usage_store_test.go` (new — save/load, missing, invalid, bad version, mkdir, ledger persist/restore, restart recovery, project switch, empty, invalid-but-usable, concurrent updates)
  - `internal/session/usage.go` (ledger store/log fields, `persistLocked`, `open`/`restoreCounterLocked` replacing `reset`)
  - `internal/session/session.go` (`OpenProject` load+open+bump, `publishUsageError`, `bumpRunSeqLocked`, `runSeqFromID`)
  - `internal/session/event.go` (`EvUsageError` kind)
- Verified: `go build ./internal/...`, `go vet`, `gofmt -l` clean, `go test ./internal/session/` and `go test -race ./internal/session/` PASS.
- **Learnings for future iterations:**
  - Persistence MUST happen inside `usageLedger.add`'s mutex, not after it. Snapshotting records and saving outside the lock races: a slow goroutine can rename a stale (smaller) records slice over a newer one and silently drop usage. Because records only ever grow and adds are serialized, saving inside the lock guarantees the last write is a superset.
  - Run IDs (`run_<n>`) reset to 0 in a fresh `Session`, so after a restart a new run would reuse a persisted run's ID and merge into its totals. `OpenProject` bumps `runSeq` past the max persisted run to prevent this. Within one session, `runSeq` already keeps climbing across `OpenProject` calls, so cross-project collisions weren't possible there.
  - `usageLedger.open` restores key counters from loaded keys (format `<scope>:<index>`). Skipping this would let `nextKey` re-issue an existing key, and the dedup in `add` would then silently drop a genuine new payload after a restart.
  - A load error is deliberately non-fatal: `store.load` returns `(nil, err)`, the ledger opens empty, and `EvUsageError` is published *after* `EvProjectOpened`. The invalid file is left on disk (surfaced, not destroyed) until the next successful `save` overwrites it.
